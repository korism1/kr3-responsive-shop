# Контрольная работа №3

Тема: «Адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта».

## Описание

ShopProject — учебный сайт магазина смартфонов Samsung, Apple и Xiaomi. Проект выполнен на основе [контрольной работы №1](https://github.com/korism1/kr1-html-css-shop) с адаптацией под разные размеры экрана и исправлениями доступности.

Используются HTML, CSS и JavaScript. Bootstrap и другие CSS-фреймворки не используются.

Автор: Хасьянов Тимур Равилевич, группа ЭФБО-03-25.

Репозиторий: https://github.com/korism1/kr3-responsive-shop

## Страницы

- `index.html` — главная страница с hero-блоком, рекомендациями по выбору и карточками товаров.
- `catalog.html` — каталог смартфонов с боковым блоком фильтров.
- `product.html` — карточка Samsung Galaxy A55 и таблица характеристик.
- `order.html` — форма заявки.
- `contacts.html` — контактная информация, карта и форма обратной связи.

## Запуск

Откройте `index.html` в браузере или запустите сайт через расширение Live Server в VS Code. Установка зависимостей и сборка не требуются.

## Адаптивная вёрстка — практическая работа №12

- На всех страницах указан `viewport`, файл `responsive.css` подключён после `style.css`.
- В `style.css` находится основное оформление, в `responsive.css` — правила адаптации по примерам методички.
- Применён подход Mobile First и медиазапросы `min-width`.
- Навигация на телефоне располагается вертикально, на большом экране — в строку.
- Hero-блок, сетка карточек и каталог адаптируются к ширине экрана.
- На телефоне фильтр расположен над товарами, на большом экране — сбоку. Реализовано оформление фильтра без JavaScript-фильтрации.
- Используются Flexbox и CSS Grid.
- Изображения ограничены шириной контейнера; применяются `srcset`, `sizes`, `picture` и версии WebP. Для изображений указаны размеры и alt, для карточек — отложенная загрузка.
- Форма заявки перестраивается из одной колонки в две, поля и кнопки остаются доступными на небольших экранах.
- Таблица характеристик прокручивается внутри отдельного контейнера.
- Модальное окно ограничено размерами экрана и допускает прокрутку.
- Футер прижат к низу окна на коротких страницах.

## Доступность — практическая работа №13

- Используются семантические элементы и один заголовок `h1` на каждой странице.
- Добавлена ссылка пропуска к основному содержимому — skip-link.
- Текущая страница обозначена через `aria-current`, для клавиатурной навигации предусмотрен видимый фокус.
- Поля связаны с `label`, подсказка телефона — через `aria-describedby`.
- Формы проверяются встроенными средствами браузера, как в КР №1: `checkValidity()` и `reportValidity()`. Ошибочные поля отмечаются `aria-invalid`.
- Диалог имеет заголовок и кнопку закрытия, закрывается по Escape и возвращает фокус на кнопку открытия.
- У таблицы есть `caption` и заголовки со `scope`.

JavaScript используется для модального окна и проверки форм. Данные форм на сервер не отправляются.

## Проверка — практическая работа №14

Страницы проверены на ширинах **360, 430, 768, 1024 и 1440 px**. Проверены навигация, карточки, изображения, формы, таблица и модальное окно. Таблица имеет собственную горизонтальную прокрутку.

В Lighthouse проверены `index.html`, `catalog.html` и `order.html` в категории **Accessibility**. Результат проверки каждой страницы — **100/100**.

В папке `lighthouse` сохранён [скриншот проверки каталога](lighthouse/accessibility-report.png): на нём видны адрес `catalog.html`, категория Accessibility и оценка 100. PNG используется вместо HTML-отчёта, как допускается в методичках №13 и №14.

Автоматическая проверка дополнена проверкой клавиатурных сценариев. Экранный диктор отдельно не проверялся.
